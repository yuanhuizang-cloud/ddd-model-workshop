# DDD 模型工坊 · 订舱代码案例

三个实现展示不同层次的业务规则与一致性协议。代码仅依赖标准库，无需联网；测试使用临时数据库。

## Python 3.9+

```sh
cd python
python3 -m unittest -v
```

- `model.py`：容量领域模型与预订命令。
- `booking.py`：乐观版本、幂等回执、业务状态与 Outbox 的 SQLite 原子提交。
- `lifecycle.py`：预留、确认、取消、过期、可恢复扫描、单工作者 Relay、Inbox 去重和状态快照投影。
- `test_booking.py` 与 `test_lifecycle.py`：规则边界、并发争抢、重复命令、回滚、发送后崩溃重发、乱序投影。

生命周期示例中，ACTIVE 和 CONFIRMED 占用容量；CANCELLED 和 EXPIRED 不占容量。确认要求服务端时间严格早于截止时间；取消和过期重复执行不得再次释放。容量、预订、回执和待发事件在本地事务内一起提交。

`lifecycle.py` 使用 SQLite 的 BEGIN IMMEDIATE 串行化写入，与 `booking.py` 的加载快照再条件提交形成对照。不要将 SQLite 的写锁粒度当作 PostgreSQL 等数据库的通用行为。

消息交付用回调连接两个 SQLite 数据库，未接入真实 MQ。Relay 发送后、标记前崩溃会重发；Inbox 与本地投影同事务提交。较新版本覆盖较旧版本只适用于此处的完整状态快照，不能直接用于金额增量事件。

## Go 1.22+

```sh
cd go
go test -race ./...
```

- `booking.go`：容量规则、值快照、版本检测、幂等与原子内存提交。
- `booking_test.go`：边界、冲突、并发与重复意图。

内存适配器使用 mutex，进程退出即丢失，不提供持久化消息保证。Go 示例聚焦初始预订；生命周期扩展在 Python 示例中串讲。

## 阅读顺序

先读模型如何表达一条规则，再看提交协议如何保护它，最后沿测试观察失败时间线。网站第 6、19、20 章分别解释聚合边界、一致性机制与完整用例。

## 实现范围

案例是单租户、单航次、整数容量的教学实现，未包括认证授权、退款、履约后取消、真实 MQ、外部支付、规则迁移、分布式时钟协议及生产监控。取消已确认预订是本案例的业务约定，不是所有订舱业务的通则。到期扫描示例面向小数据量，生产需要适当索引、分批、任务领取与监控。

可执行测试验证本实现的协议，不代表其他数据库和基础设施会自动提供相同保证。
